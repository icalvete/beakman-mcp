Para gente técnica

Monta tu propio Beakman

Tu propio servidor de Beakman, con tu temario, que se actualiza solo cada vez que cambias el repositorio.

¿Solo quieres usarlo? No necesitas nada de esto: sigue la guía de uso. Esta guía es para quien quiere su propia copia, por ejemplo un profe con su programación.

Qué vas a montar

Un servidor MCP pequeño, en un contenedor, detrás de HTTPS. No ejecuta ningún modelo de IA: entrega a Claude las instrucciones de Beakman y el temario, y la IA corre en la cuenta de quien estudia. Lee el contenido de tu fork en GitHub y comprueba cada cinco minutos si hay cambios, así que editar el repositorio basta.

Necesitas: una cuenta de GitHub, un servidor con Docker y un dominio con HTTPS. Tiempo: unos 20 minutos.

1. Haz un fork

Haz un fork de icalvete/beakman-mcp. Tiene que ser público, porque el servidor lee el contenido sin credenciales.

  • beakman/base.md: la personalidad y el método, comunes a todas las asignaturas.
  • <asignatura>/asignatura.md: lo propio de cada asignatura.
  • <asignatura>/1eso/ y 2eso/: los temas, un fichero por tema. Un curso con varias asignaturas, como Ciencias de 2º, lleva una subcarpeta por asignatura con un _titulo.txt.
  • mcp/: el servidor, en Python.

2. Arranca el servidor

La imagen está publicada y es pública. Dile qué repositorio leer y con qué dominio la vas a servir:

docker run -d --name beakman --restart unless-stopped -p 127.0.0.1:8000:8000 \
  -e BEAKMAN_GITHUB_REPO=TU_USUARIO/beakman-mcp \
  -e BEAKMAN_ALLOWED_HOSTS=beakman.tudominio.com \
  ghcr.io/icalvete/beakman-mcp:latest

Comprueba que ha cargado tu temario:

curl -s -H "Host: beakman.tudominio.com" localhost:8000/up

Debe responder con "ok": true, el commit que ha leído y las cuatro asignaturas.

VariablePara qué
BEAKMAN_GITHUB_REPOEl repositorio del que lee el temario. Por defecto, icalvete/beakman-mcp.
BEAKMAN_GITHUB_BRANCHLa rama. Por defecto, main.
BEAKMAN_ALLOWED_HOSTSLos dominios con los que se puede llamar al servidor, separados por comas. Protege contra ataques de DNS rebinding.
BEAKMAN_REFRESH_SECONDSCada cuánto mira si hay cambios. Por defecto, 300.

Opcional: la entrada

Sin estas variables, el servidor no pide entrar y no guarda nada de nadie. Con BEAKMAN_ENTRADA_URL, Claude abre la página «Preséntate» al conectar, como en beakman.kademy.net. Monta un volumen en /data para que la base de datos no se pierda (-v beakman-data:/data).

VariablePara qué
BEAKMAN_ENTRADA_URLLa URL base del servidor con entrada, por ejemplo https://beakman.tudominio.com. Sin ella, no hay entrada.
BEAKMAN_DBDónde va la base de datos SQLite. Por defecto, /data/beakman.sqlite.
BEAKMAN_ENTRADA_CORREOSLos correos que pueden entrar con datos, separados por comas. Vacía, no entra nadie con datos. Con *, cualquiera. Entrar sin datos funciona siempre.
BEAKMAN_SMTP_HOST, _PORT, _USER, _PASSWORDEl servidor de correo para mandar las confirmaciones y los enlaces.
BEAKMAN_MAIL_FROMEl remitente de los correos.
TURNSTILE_SITE_KEY, TURNSTILE_SECRET_KEYLas claves de Cloudflare Turnstile, la comprobación contra robots de la página de entrada. Sin ellas, no se comprueba (solo para probar en local).

Si guardas datos de familias, cuenta en tu web qué guardas y cómo se borra, como hace la página de privacidad de Beakman.

Para probar en local con una copia del repositorio, sin GitHub: BEAKMAN_REPO_DIR=$PWD uvicorn beakman_mcp.server:app --app-dir mcp.

3. Ponlo detrás de HTTPS

Claude se conecta desde la nube de Anthropic, así que el servidor necesita una dirección pública con HTTPS. Con Caddy basta con esto, y el certificado lo saca él solo:

beakman.tudominio.com {
    reverse_proxy 127.0.0.1:8000
}

Crea en tu DNS un registro A para beakman.tudominio.com con la IP del servidor.

4. Conéctalo a Claude

En claude.ai → Ajustes → Conectores, pulsa Agregar conector personalizado con la URL https://beakman.tudominio.com/mcp. Si usas la entrada, deja lo que viene marcado, pulsa Agregar y luego Conectar. En un chat nuevo, escribe «Quiero estudiar historia con Beakman».

Sirve cualquier cliente MCP que admita servidores remotos por HTTP. Hoy, desde España, el que lo permite en cuentas personales es Claude.

5. Edita y listo

  • Cómo es Beakman o cómo explica: beakman/base.md.
  • Algo de una asignatura: su asignatura.md.
  • Un tema nuevo: un fichero en 1eso/ o 2eso/, empezando por su número.

Haces push y, en cinco minutos como mucho, el servidor tiene el contenido nuevo. El código del servidor no lee nada ejecutable del repositorio: solo textos.

6. Opcional: ficheros para Drive

El repositorio trae también un Action, Sincronizar con Drive, que genera tres ficheros por asignatura y los sube a Google Drive con rclone. Sirve para darle el temario a otras herramientas que leen de Drive. Necesita el secreto RCLONE_CONF con un remote de rclone llamado beakman y el permiso drive.file, con tu propia app de Google en producción. Si no lo usas, desactívalo en la pestaña Actions de tu fork, o fallará en cada push.

7. Si algo falla

Qué pasaPor qué y qué hacer
/up da error al arrancarNo ha podido leer el repositorio. Comprueba que el fork es público y el nombre de BEAKMAN_GITHUB_REPO.
El servidor responde 400El dominio no está en BEAKMAN_ALLOWED_HOSTS.
Claude no consigue conectarLa URL tiene que ser pública, con HTTPS y acabar en /mcp.
Claude no habla como BeakmanPídele que empiece la clase con Beakman: «Quiero estudiar historia con Beakman». Un proyecto de Claude con esa instrucción ayuda: lo cuenta la guía de uso.
Un cambio no apareceEspera cinco minutos y abre un chat nuevo. /up dice qué commit está usando.

¿Te ha servido? Beakman es gratis y lo seguirá siendo. Escribir y revisar los temarios lleva muchas horas: si quieres ayudar a mantenerlo, puedes hacerlo con GitHub Sponsors. Avisar de un error en un tema también ayuda mucho.
