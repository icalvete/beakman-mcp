Para gente técnica

Monta tu propio Beakman

Haz un fork, conecta tu Google Drive y crea tus Gems. Después, cada cambio en tu repositorio llega solo a los Gems.

Necesitas una cuenta de GitHub, una cuenta de Google, rclone y gh instalados en tu ordenador. Si sabes usar git, te sobra para seguir la guía.

En esta página
  1. Haz un fork
  2. Crea tus credenciales de Google
  3. Configura rclone
  4. Guarda el secreto en GitHub
  5. Lanza el Action
  6. Crea cada Gem
  7. Edita y listo

1. Haz un fork

Haz un fork de icalvete/beakman-gems y clónalo.

GitHub desactiva los Actions en los forks. Actívalos en la pestaña Actions de tu fork.

Lo que hay dentro:

  • beakman/base.md: la personalidad y el método, comunes a todas las asignaturas.
  • beakman/gem_stub.txt: el texto corto y fijo que va en la caja de instrucciones de cada Gem.
  • <asignatura>/asignatura.md: lo propio de cada asignatura. Su cabecera lleva el nombre, el nombre del Gem y la descripción.
  • <asignatura>/1eso/ y 2eso/: los temas, un fichero por tema.
  • scripts/build.py: genera los ficheros de cada Gem en dist/.
  • .github/workflows/sync-drive.yml: el Action que genera y sube a Drive.

Puedes probar el build en local con python3 scripts/build.py. Con --check solo comprueba, sin escribir nada.

2. Crea tus credenciales de Google

rclone trae un client_id compartido, pero tiene cuotas bajas y Google lo limita a menudo. Mejor uno tuyo. Es gratis.

  1. Entra en Google Cloud Console y crea un proyecto. Por ejemplo, beakman.
  2. En APIs y servicios → Biblioteca, busca Google Drive API y habilítala.
  3. Configura la pantalla de consentimiento de OAuth con tipo de usuario Externo. Rellena el nombre y tu correo. No hace falta añadir permisos aquí.
  4. Publica la app en producción. En estado de prueba («Testing»), el refresh token caduca a los 7 días y el Action deja de funcionar. Al publicarla, Google puede avisar de que la app no está verificada. Para uso propio no importa: al autorizar, pulsa «Configuración avanzada» y continúa.
  5. En Credenciales → Crear credenciales → ID de cliente de OAuth, elige el tipo Aplicación de escritorio. Apunta el ID de cliente y el secreto de cliente.

3. Configura rclone

Crea un remote que se llame beakman. El Action usa ese nombre.

rclone config create beakman drive \
  scope=drive.file \
  client_id=TU_CLIENT_ID \
  client_secret=TU_CLIENT_SECRET

Se abre el navegador para que autorices el acceso con tu cuenta de Google. Al terminar, la configuración queda en ~/.config/rclone/rclone.conf.

Por qué drive.file. Con ese permiso, rclone solo ve los ficheros que crea él. No puede leer ni tocar el resto de tu Drive. Si el secreto se filtrara algún día, el daño se queda en la carpeta de Beakman.

La otra cara: si subes los ficheros a mano por la web de Drive, rclone no los ve y crea otros nuevos. Deja que los cree el Action.

4. Guarda el secreto en GitHub

Desde la carpeta de tu fork:

gh secret set RCLONE_CONF < ~/.config/rclone/rclone.conf

Así el fichero va directo de tu disco a GitHub, sin pasar por la pantalla ni el historial. Si tu rclone.conf tiene más remotes, mejor crea uno aparte solo con el de beakman.

5. Lanza el Action

En la pestaña Actions, elige Sincronizar con Drive y pulsa Run workflow. O desde la terminal:

gh workflow run sync-drive.yml

A partir de ahora se lanza solo en cada push a main que toque el contenido.

Al acabar, en tu Drive aparece una carpeta Beakman con una subcarpeta por asignatura: Historia, Matematicas, Ciencias y Lengua. Cada una tiene tres ficheros:

  • Beakman_<Asignatura>_00_Instrucciones.txt
  • Beakman_<Asignatura>_01_Curso_1ESO.txt
  • Beakman_<Asignatura>_02_Curso_2ESO.txt

En cada ejecución se sobrescriben y conservan su identificador de Drive. Por eso los Gems ven los cambios sin hacer nada.

6. Crea cada Gem

Este paso es a mano porque Gemini no tiene una API para crear Gems. Se hace una vez por asignatura.

Ejecuta python3 scripts/build.py en local. Te deja en dist/<Asignatura>/gem.txt todo lo que hay que pegar: nombre, descripción, instrucciones y la lista de ficheros.

  1. Abre Gemini con la misma cuenta de Google que autorizó rclone. Ve a Gems → Nuevo Gem.
  2. Pega el nombre y la descripción de gem.txt.
  3. En Instrucciones, pega el texto fijo de gem.txt. Sale de beakman/gem_stub.txt con el nombre de la asignatura ya puesto. Solo dice que siga el fichero de instrucciones.
  4. En Conocimiento, añade los tres ficheros desde Google Drive, de la carpeta Beakman/<Asignatura>. Enlázalos desde Drive, no los subas desde el ordenador: si los subes, el Gem se queda con una copia que no se actualiza.
  5. Guarda el Gem y pruébalo escribiendo «Ayuda».
  6. Compártelo con enlace, con permiso de lector. Ese enlace es el que das a familias y alumnos.

Si quieres publicar tu propia página, cambia los href="#" de docs/index.html por tus enlaces. Cada botón tiene un comentario GEM_URL_… encima.

7. Edita y listo

A partir de aquí, para cambiar a Beakman solo editas el repositorio:

  • Para cambiar su forma de ser o el método, beakman/base.md.
  • Para algo de una asignatura, su asignatura.md.
  • Para añadir un tema, un fichero nuevo en 1eso/ o 2eso/. Se ordenan por nombre, así que empieza por el número.

Haces push y el Action hace el resto. Nadie copia nada a mano.

No cambies los nombres de los tres ficheros de Drive ni los borres. El Gem los enlaza por su identificador. Si uno desaparece, hay que volver a enlazarlo a mano en el Gem.
